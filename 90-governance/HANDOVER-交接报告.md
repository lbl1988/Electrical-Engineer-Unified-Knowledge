**三条铁律**（README §1，不可违反）：

## 5. 治理机制（接手即生效）

- **版本信息只认白名单 8 源**，公众号/网盘转录只能作线索，须双独立来源交叉验证后才可入库（历史上靠此方法修正过 OCR 噪声，如"CD-55020-2022"→GB 55029-2022）；
- **监控节奏**：月度盯强制规范与考纲相关标准 → 季度全量盘点（产出记录入 90-governance/）→ 半年核国际标准 → 年度配合考纲发布重建 60-exam；
- **换版响应**：新版本实施 → 按 05 模板写 CHG → 在 changelog 表格登记 → 逐条修正受影响条目 → commit。

## 6. 质量方法论（已验证的写作纪律，务必延续）

1. **算例数字全部手工复算**：每个中间值先在草稿中复算，不自洽不落盘；
2. **方法严谨优先于数字吻合**：遇预告值与复算不符时，改为双工况设计对照，而非凑数；
3. **不确定值显式标注**：照度档位、具体条文号、Kc 曲线精确值等一律写"以正式文本/曲线为准"；
4. **典型易错点固化为"常见错误"表**：如 c 系数双重计入、GB 51309 与 DL/T 5044 双体系公式不混用、10/350μs 与 8/20μs 不可互换；
5. **条目交叉引用成网**：TH→CALC→PR→CASE 四层链，每条至少一个上游引用＋一个下游应用，被引条目须回写"下游案例"行。

## 10. 维护操作 SOP

**新增条目**：读 `01-编号规则`＋`02-写作规范` → 套对应模板（03/04/05/06）→ 算例手工复算 → front matter 填 `standards` 数组 → 建立上下游交叉引用（并回写被引用条目的关联段）→ 更新所在目录 README 索引表与 kb/README.md 统计 → `git add -A && git commit -m "{条目ID}: {动作} {说明}"`。

**新增案例（批量）**：规划5条主题与引用链 → 按 `06-模板-案例类` 填充九段式 → 校验 YAML frontmatter（`---`非`***`、`}`非`|`、列表无转义）→ 回写支撑条目下游案例引用 → 更新 `50-case/README.md`（批次表+引用网+累计统计）→ 更新主 `README.md` 版本号 → 提交推送。

**标准换版**：白名单源核实 → 写 CHG（05 模板）→ 全库 grep 旧标准号定位受影响条目 → 逐条更新 → commit。

**季度盘点**：按 GOV-001 §3 节奏逐源核查 → 仿 GOV-002 格式产出 `YYYYQ{n}-盘点记录.md` → 遗留事项显式列出并转入下季度。

**YAML 损坏修复**：历史出现 `***` 替换 `---`、`\` 转义列表、`|` 替换 `}` 三类笔误。发现后用 `git checkout HEAD -- <file>` 或 `git restore --source=HEAD --staged --worktree <file>` 恢复，再手动重新回写。
