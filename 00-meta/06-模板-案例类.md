# 条目模板 · 案例类九段式变体（CASE 域专用）

> 使用方法：复制本模板，替换 `{}` 占位符；理论类条目用 META-004 五段式，实践类用 META-003 九段式。
> 与实践类九段式的差异：案例类聚焦"背景→方案→计算→审查意见→整改→经验教训"的真实/脱敏复盘链路，每条必须完成标准溯源与脱敏处理。

```markdown
---
id: CASE-{三位序号}
title: {中文标题}
domain: CASE
subdomain: {EX|DR|AC|CP}
case_type: {exam|review|accident|composite}
year_source: {2026 / 校审通报 / 事故调查报告 / 综合设计}
desensitized: true
voltage_levels: [{LV/MV/HV/EHV/UHV}]
lifecycle: {规划/设计/施工/验收/运维}
standards:
  - { code: {标准号-年份}, clause: "{条款号}", note: {引用要点} }
status: draft
reviewers: []
version: 0.1
updated: {YYYY-MM-DD}
---

# {标题}

## 1. 摘要

（一段话：案例类型 / 涉及工程场景 / 关键结论或教训。≤150 字，末句以"教训："开头给一句话总结）

## 2. 背景

（工程概况 / 真题出处 / 事故经过；脱敏后项目代号"某 XX 工程"；真题保留年度与题面摘要；事故注明通报来源与时间）

## 3. 方案

（原设计方案或原答题要点：系统结构 / 设备选型 / 整定值 / 关键参数表）

## 4. 计算

（关键复算：引用 [CALC-*] 公式与数据链，每步标注依据；算例数据须与被引条目自洽）

| 符号 | 含义 | 取值 | 来源 |
|---|---|---|---|

## 5. 审查意见

（校审意见 / 规范不符项 / 调查结论，逐条挂"标准号-年份＋条款号"）

| 序号 | 意见 / 结论 | 不符条款 | 后果 |
|---|---|---|---|

## 6. 整改

（修改方案或替代设计：整改后参数 / 新增措施 / 验收复查结论）

## 7. 经验教训

（可复用要点 3-5 条，每条以动词开头，校审/设计/运维可直接勾选）

- [ ] 要点 1
- [ ] 要点 2
- [ ] 要点 3

## 8. 关联条目

- 上游：{TH/CALC/PR/标准条目链接}
- 下游：{被本案例支撑的条目}
- 平行：{同类 CASE 或相关 PR}

## 9. 变更记录

| 版本 | 日期 | 修改内容 | 修改人 |
|---|---|---|---|
```

## 案例子域代码（front matter `subdomain` 字段）

| 代码 | 子域 | case_type 值 | 说明 |
|---|---|---|---|
| EX | 真题拆解 | exam | 注册电气工程师历年真题，按知识单元×年份 |
| DR | 校审问题 | review | 典型设计错误与审查意见，按域分类 |
| AC | 事故复盘 | accident | 基于公开调查报告的电气事故分析 |
| CP | 综合协同 | composite | 多专业协同综合案例 |

> 子域代码仅入 front matter `subdomain`，**不嵌入文件名**（遵守 `CASE-{三位序号}-{英文短名}.md` 格式）。
